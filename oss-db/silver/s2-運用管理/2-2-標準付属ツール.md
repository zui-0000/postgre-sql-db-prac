# S2.2 標準付属ツールの使い方

- 重要度: **5** / 50
- 公式の説明: 「OSのコマンドプロンプトから実行できる管理用ツールの使い方を問う」
- 実習環境: db（`psql`、`createdb` など）、sandbox（`pg_ctl`、`pg_controldata`、`pg_resetwal`）

## 出題範囲

### 主要な知識範囲

- データベース管理用コマンドの使い方

### 重要な用語、コマンド、パラメータなど

`pg_ctl` / `createuser` / `dropuser` / `createdb` / `dropdb` / `psql` / `pg_config` / `pg_controldata` / `pg_isready` / `pg_resetwal` / メタコマンド

## 学習メモ

### ツールの全体像

| コマンド | 役割 | SQL でいうと |
| --- | --- | --- |
| `pg_ctl` | サーバーの起動、停止、再起動、リロード、状態確認 | （SQL では操作できない） |
| `createuser` / `dropuser` | ロールの作成と削除 | `CREATE ROLE` / `DROP ROLE` のラッパー |
| `createdb` / `dropdb` | データベースの作成と削除 | `CREATE DATABASE` / `DROP DATABASE` のラッパー |
| `psql` | 対話的に SQL を実行するクライアント | — |
| `pg_config` | インストール情報（バージョン、ディレクトリ）の表示 | — |
| `pg_controldata` | クラスタの制御情報の表示 | — |
| `pg_isready` | サーバーが接続を受け付けているかの確認 | — |
| `pg_resetwal` | WAL を消去して制御情報を初期化する（最後の手段） | — |

`createuser` などは「SQL のラッパー」である点が重要。OS のコマンドプロンプトから実行できるが、内部では普通の SQL が実行されている。

### pg_ctl

サーバーのライフサイクルを扱うコマンド。データディレクトリは `-D` で指定する（`PGDATA` 環境変数でも可）。

| モード | 動作 |
| --- | --- |
| `start` | サーバーをバックグラウンドで起動する |
| `stop` | サーバーを停止する |
| `restart` | 停止してから起動する |
| `reload` | 設定ファイルを読み直す（SIGHUP を送る） |
| `status` | 起動しているかを確認する |
| `promote` | スタンバイサーバーを昇格させる |
| `init` / `initdb` | `initdb` を呼び出してクラスタを作る（Ver.3.0 の改定で出題範囲から削除された） |

| オプション | 意味 |
| --- | --- |
| `-D` / `--pgdata` | データディレクトリの場所 |
| `-l` / `--log` | サーバーのログの出力先ファイル |
| `-m` / `--mode` | 停止モード（`smart`、`fast`、`immediate`） |
| `-w` / `--wait` | 完了を待つ（`start`、`stop`、`restart`、`promote` では既定） |
| `-W` / `--no-wait` | 完了を待たない |

#### 停止モード

| モード | 動作 |
| --- | --- |
| `smart` | 新しい接続を受け付けず、**接続中のクライアントが切断するまで待つ** |
| `fast`（**既定**） | クライアントの切断を待たない。実行中のトランザクションはロールバックされ、強制的に切断される |
| `immediate` | サーバープロセスを直ちに中断する。**次回の起動時にクラッシュリカバリが必要になる** |

#### 実機で確認した結果

```text
### 停止中の pg_ctl status
pg_ctl: no server running
  exit=3                       ← 停止中は終了コード 3

### start
waiting for server to start.... done
server started
  exit=0

### 起動中の pg_ctl status
pg_ctl: server is running (PID: 113)
  exit=0

### reload（設定の再読み込み）
server signaled
  exit=0
```

`status` の終了コードは、**サーバーが停止していれば 3**、データディレクトリを特定できなければ 4 になる。シェルスクリプトから状態を判定するときに使える。

`immediate` で停止すると、クラスタの状態が正常終了時の `shut down` ではなく `in production` のまま残る。

```text
### immediate で停止したあとのクラスタ状態
Database cluster state:               in production

### 次の起動でクラッシュリカバリになるか（ログ）
LOG:  checkpoint starting: end-of-recovery immediate wait
LOG:  database system is ready to accept connections
```

次の起動時にリカバリ処理（`end-of-recovery` のチェックポイント）が走っているのが確認できる。

### createuser と createdb

どちらも SQL のラッパーなので、`-e`（`--echo`）を付けると**実際に実行される SQL が表示される**。

```sh
createuser -U postgres -e --createdb appuser
createdb  -U postgres -e -O appuser appdb
dropdb    -U postgres -e appdb
dropuser  -U postgres -e appuser
```

```sql
CREATE ROLE appuser NOSUPERUSER CREATEDB NOCREATEROLE INHERIT LOGIN NOREPLICATION NOBYPASSRLS;
CREATE DATABASE appdb OWNER appuser;
DROP DATABASE appdb;
DROP ROLE appuser;
```

オプションを何も付けない場合の既定値が、この出力からわかる。**スーパーユーザーではない、データベースを作れない、ロールを作れない、ログインできる、権限を継承する**。

| `createuser` のオプション | 意味 |
| --- | --- |
| `-s` / `--superuser` | スーパーユーザーにする |
| `-d` / `--createdb` | データベースを作成できるようにする（既定は `-D`、作成不可） |
| `-r` / `--createrole` | ほかのロールを作成できるようにする（既定は `-R`） |
| `-L` / `--no-login` | ログインできないロールにする（既定は `-l`、ログイン可） |
| `-P` / `--pwprompt` | パスワードの入力を求める |
| `-g` / `--member-of` | 既存のロールのメンバーにする |
| `-e` / `--echo` | 実行する SQL を表示する |

`createuser` を実行できるのは、**スーパーユーザーか `CREATEROLE` 権限を持つユーザー**だけ。

| `createdb` のオプション | 意味 |
| --- | --- |
| `-O` / `--owner` | データベースの所有者を指定する |
| `-T` / `--template` | コピー元のテンプレートを指定する（`-T template0` など） |
| `-E` / `--encoding` | エンコーディングを指定する |
| `-l` / `--locale` | ロケールを指定する |
| `-D` / `--tablespace` | 既定のテーブルスペースを指定する |
| `-e` / `--echo` | 実行する SQL を表示する |

**データベース名を省略すると、実行した OS ユーザーと同じ名前のデータベースが作られる。** `createdb` の `-D` はテーブルスペースの指定で、`pg_ctl` や `initdb` の `-D`（データディレクトリ）とは意味が違う点に注意する。

#### createdb と CREATE DATABASE は別物

`createdb` は `CREATE DATABASE` を小文字にしたものではない。名前が似ているだけで、実行する場所が違う。

| | `CREATE DATABASE` | `createdb` |
| --- | --- | --- |
| 正体 | **SQL 文** | **OS のコマンド（プログラム）** |
| 実行する場所 | psql などの中 | OS のシェル |
| 大文字と小文字 | 区別しない（`create database` でも動く） | **区別する**（Linux のコマンドなので） |

実機で確認した結果:

```text
psql の中で createdb foo;   → ERROR:  syntax error at or near "createdb"
シェルで createdb           → 成功
シェルで CREATEDB           → bash: CREATEDB: command not found
```

`createdb` は、内部で `CREATE DATABASE` をサーバーに送るラッパーである。SQL のキーワードと識別子の大文字・小文字の扱いは、[S3.1 の 02 テーブルと制約](../s3-開発SQL/3-1-SQLコマンド/02-テーブルと制約.md)で扱う。

### psql

| オプション | 意味 |
| --- | --- |
| `-c` / `--command` | SQL を1つ実行して終了する |
| `-f` / `--file` | ファイルから SQL を読み込んで実行する |
| `-l` / `--list` | データベースの一覧を表示して終了する |
| `-d`、`-U`、`-h`、`-p` | 接続先のデータベース、ユーザー、ホスト、ポート |
| `-A` / `--no-align` | 桁揃えをしない出力にする |
| `-t` / `--tuples-only` | ヘッダーと行数の表示を省く |
| `-x` / `--expanded` | 縦方向の拡張表示にする |
| `-X` / `--no-psqlrc` | `~/.psqlrc` を読み込まない |

#### メタコマンド

`\` で始まる、psql 自身が解釈するコマンド。SQL ではない。

| メタコマンド | 内容 |
| --- | --- |
| `\l` | データベースの一覧 |
| `\c` / `\connect` | 接続先を切り替える |
| `\d` | テーブル、ビュー、シーケンスの一覧。`\d テーブル名` で列の定義 |
| `\dt` | テーブルの一覧 |
| `\di` / `\dv` / `\dn` / `\df` | インデックス / ビュー / スキーマ / 関数の一覧 |
| `\du` / `\dg` | ロールの一覧 |
| `\x` | 拡張表示の切り替え |
| `\timing` | 実行時間の表示の切り替え |
| `\conninfo` | 現在の接続情報 |
| `\copy` | クライアント側でファイルとやり取りする COPY |
| `\i` | ファイルを読み込んで実行する |
| `\?` | メタコマンドのヘルプ |
| `\h` | SQL の構文のヘルプ（`\h CREATE TABLE` など） |
| `\q` | 終了する |

実機での出力例:

```text
=> \du
                             List of roles
 Role name |                         Attributes
-----------+------------------------------------------------------------
 postgres  | Superuser, Create role, Create DB, Replication, Bypass RLS

=> \d demo_tools
             Table "public.demo_tools"
 Column |  Type   | Collation | Nullable | Default
--------+---------+-----------+----------+---------
 id     | integer |           | not null |
 name   | text    |           | not null |
Indexes:
    "demo_tools_pkey" PRIMARY KEY, btree (id)

=> \x on
Expanded display is on.
=> SELECT 1 AS a, 'two' AS b;
-[ RECORD 1 ]
a | 1
b | two

=> \timing on
Timing is on.
=> SELECT count(*) FROM pg_class;
 count
-------
   419
Time: 0.177 ms
```

`\copy` と `COPY` の違いは [S2.4](2-4-バックアップ方法.md) で扱う。`\copy` はクライアント側のファイルを読み書きし、`COPY` はサーバー側のファイルを読み書きする。

#### MySQL との対応

| やりたいこと | MySQL | PostgreSQL（psql） |
| --- | --- | --- |
| データベースの一覧 | `SHOW DATABASES;` | `\l` |
| データベースを切り替える | `USE hoge;` | `\c hoge` |
| テーブルの一覧 | `SHOW TABLES;` | `\dt` |
| テーブルの定義 | `DESCRIBE hoge;` | `\d hoge` |
| 今のデータベース名 | `SELECT DATABASE();` | `SELECT current_database();` |

MySQL の書き方をそのまま打つと、エラーになる。

```text
SHOW DATABASES;  → ERROR:  unrecognized configuration parameter "databases"
USE mydb;        → ERROR:  syntax error at or near "USE"
```

1つ目のエラーは、**PostgreSQL の `SHOW` が設定パラメータを表示するコマンド**だから起きる（`SHOW port` など。[S2.3](2-3-設定ファイル.md) を参照）。`databases` という設定パラメータを探しに行って、見つからなかった。

#### \c は「切り替え」ではなく「接続し直し」

MySQL の `USE` は同じ接続のまま既定のデータベースを切り替えるが、psql の `\c` は**今の接続を閉じて、別のデータベースに新しく接続し直す**。接続ごとにバックエンドプロセスが作られるので、`\c` の前後でプロセス ID が変わる。

```text
### 切り替える前
 current_database | pg_backend_pid
------------------+----------------
 postgres         |         483177

You are now connected to database "mydb" as user "postgres".

### \c mydb で切り替えたあと
 current_database | pg_backend_pid
------------------+----------------
 mydb             |         483178     ← プロセスが変わった
```

PostgreSQL では**1つの接続は1つのデータベースにしか繋がらない**。そのため、別のデータベースのテーブルを SQL で直接参照することもできない。

```text
mydb から postgres のテーブルを参照 → ERROR:  cross-database references are not implemented
```

MySQL の「データベース」は、PostgreSQL の「スキーマ」に近い（詳しくは [S3.1 の 04 DBオブジェクト](../s3-開発SQL/3-1-SQLコマンド/04-DBオブジェクト.md)）。

#### 円記号（¥）とバックスラッシュ（\）は別の文字

日本語配列の Mac では、`¥` キーを押すと円記号（`¥`、U+00A5）が入力されることがある。見た目は似ていても、psql のメタコマンドに使うバックスラッシュ（`\`、U+005C）とは**別の文字**である。

```text
¥l  → ERROR:  syntax error at or near "¥l"   ← メタコマンドではなく SQL として解釈された
\l  → データベースの一覧が表示される
```

対処法:

- `Option` + `¥` でバックスラッシュを入力する
- キーボードの入力ソース（日本語）の設定で、「`¥` キーで入力する文字」を「`\`（バックスラッシュ）」に変える。変えたあとは `Option` + `¥` で円記号になる

なお、公式サイトの出題範囲で `\copy` が `¥copy` と書かれているのは、日本語の環境では `\` が `¥` のように表示されることがあるため（[S2.4](2-4-バックアップ方法.md) を参照）。

### pg_config

インストールされた PostgreSQL の情報を表示する。

```sh
pg_config --version --bindir --sharedir
```

```text
PostgreSQL 18.6 (Debian 18.6-1.pgdg13+2)
/usr/lib/postgresql/18/bin
/usr/share/postgresql/18
```

### pg_controldata

クラスタの制御情報（`pg_control` ファイルの内容）を表示する。**サーバーが停止していても実行できる**ので、クラスタの状態を調べるのに使う。

```sh
pg_controldata -D ~/s22
```

```text
pg_control version number:            1800
Catalog version number:               202506291
Database cluster state:               shut down
Data page checksum version:           1
```

`Database cluster state` の主な値:

| 値 | 意味 |
| --- | --- |
| `in production` | 起動中（または異常終了してそのまま残った状態） |
| `shut down` | 正常に停止した |
| `in archive recovery` | リカバリ中 |

### pg_isready

サーバーが接続を受け付けているかを確認する。**終了コードで結果を判断する**ので、監視スクリプトや起動待ちの処理に向いている（[環境構築](../../../docs/01-環境構築.md)の healthcheck でも使っている）。

| 終了コード | 意味 |
| ---: | --- |
| 0 | 接続を正常に受け付けている |
| 1 | 接続を拒否している（起動処理中など） |
| 2 | 応答がなかった |
| 3 | 接続を試みなかった（パラメータが不正など） |

```text
$ pg_isready
/var/run/postgresql:5432 - accepting connections
  exit=0

$ pg_isready -p 5433
/var/run/postgresql:5433 - no response
  exit=2
```

### pg_resetwal

**WAL を消去して、`pg_control` の制御情報を初期化する**コマンド。ファイルが壊れてサーバーが起動しなくなったときの、**最後の手段**として使う。

公式ドキュメントの警告:

- 「それ以外の用途で使うのは危険であり、細心の注意を払う必要がある」
- 実行後はサーバーを起動できるようになるかもしれないが、**中途半端にコミットされたトランザクションのせいでデータが矛盾している可能性がある**。すぐにダンプを取り、`initdb` でクラスタを作り直して、リストアすること
- ダンプを取る前に、データを変更する操作をしてはいけない

安全のための制約もある。**サーバーが起動しているときは実行できない**。

```text
$ pg_resetwal -D ~/s22
pg_resetwal: error: lock file "postmaster.pid" exists
pg_resetwal: hint: Is a server running?  If not, delete the lock file and try again.
  exit=1
```

- データディレクトリへの読み書きが必要なので、**サーバーをインストールしたユーザー（データディレクトリの所有者）でしか実行できない**。
- `-D` でデータディレクトリを明示的に指定する必要がある。
- `-f` / `--force` は、正常に停止していない場合など、危険な状況でも強行するためのオプション。

### 試験の観点

- `createuser` と `createdb` は **SQL のラッパー**。`-e` で実行される SQL が見える。
- `createuser` の既定は「スーパーユーザーではない、データベースを作れない、ロールを作れない、ログインできる」。
- **`pg_ctl stop` の既定の停止モードは `fast`**。`smart` は接続が切れるまで待ち、`immediate` はクラッシュリカバリが必要になる。
- **`pg_ctl status` は、停止中なら終了コード 3**。
- **`pg_isready` の終了コードは 0 / 1 / 2 / 3**。
- **`pg_resetwal` は最後の手段**。サーバー起動中は実行できず、実行後はダンプとリストアが必要。
- Ver.3.0 の改定で `pg_config`、`pg_controldata`、`pg_isready`、`pg_resetwal` が出題範囲に追加された。

## 確認問題

### 問1（選択）

`pg_ctl stop` の既定の停止モードはどれか。

- A. `smart`
- B. `fast`
- C. `immediate`
- D. 既定はなく、必ず `-m` の指定が必要

### 問2（入力）

サーバーが接続を受け付けているかを確認し、結果を終了コードで返すコマンドの名前を答えよ。

### 問3（全て選択）

`createuser` について、正しいものをすべて選べ。

- A. `CREATE ROLE` のラッパーである
- B. オプションを付けない場合、作られるロールはログインできる
- C. オプションを付けない場合、作られるロールはデータベースを作成できる
- D. 実行できるのはスーパーユーザーか `CREATEROLE` 権限を持つユーザーだけである
- E. `-e` を付けると、実行される SQL が表示される

### 問4（選択）

`pg_resetwal` について、正しいものを1つ選べ。

- A. サーバーを起動したまま実行できる
- B. WAL を消去するので、実行後はそのまま運用を続けてよい
- C. サーバーが起動しない障害時の最後の手段であり、実行後はダンプとリストアが必要
- D. root で実行する必要がある

### 問5（選択）

サーバーが停止している状態で `pg_ctl status` を実行したときの終了コードはどれか。

- A. 0
- B. 1
- C. 3
- D. 4

### 問6（選択）

psql のメタコマンドと内容の組み合わせとして、**誤っている**ものを1つ選べ。

- A. `\l` ― データベースの一覧
- B. `\du` ― ロールの一覧
- C. `\dt` ― テーブルの一覧
- D. `\c` ― 接続を切断して psql を終了する

### 問7（選択）

psql に接続した状態で `createdb mydb;` と入力した。結果として正しいものを1つ選べ。

- A. `mydb` というデータベースが作られる
- B. 構文エラーになる
- C. `createdb` コマンドが起動し、`mydb` が作られる
- D. 小文字なので無視される

### 解答

| 問 | 答え | 解説 |
| --- | --- | --- |
| 1 | B | 既定は `fast`。クライアントの切断を待たず、実行中のトランザクションはロールバックされる |
| 2 | `pg_isready` | 0 は受付中、1 は拒否、2 は無応答、3 は試行せず |
| 3 | A、B、D、E | 既定ではデータベースを作成できない（`-d` を付けると作成可）ので C が誤り |
| 4 | C | 起動中は `postmaster.pid` があるため実行できない。データディレクトリの所有者が実行する |
| 5 | C | 停止中は 3、データディレクトリを特定できない場合は 4 |
| 6 | D | `\c` は接続先の切り替え。終了は `\q` |
| 7 | B | `createdb` は OS のシェルで実行するコマンドで、SQL ではない。psql の中で SQL として作るなら `CREATE DATABASE mydb;`（小文字の `create database mydb;` でも動く） |
