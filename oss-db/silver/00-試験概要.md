# OSS-DB Silver 試験概要

調査日: 2026-09-14（情報源は末尾の「参考リンク」）

## 試験の基本情報

| 項目 | 内容 |
| --- | --- |
| 試験名 | OSS-DB Exam Silver（Ver.3.0） |
| 試験番号 | OSDBS-03 |
| 基準の RDBMS | PostgreSQL 12〜14（公式の表記は「PostgreSQL 12以上」「2023年2月現在、14まで対応」） |
| 出題形式 | CBT。マウスで選ぶ問題がほとんどで、キーボードで入力する問題も少しある |
| 問題数 | 約50問 |
| 試験時間 | 90分（うち5分はアンケート）※ |
| 合格ライン | 正答率 64% が目安 ※ |
| 受験料 | 16,500円（税込） |
| 受験方法 | テストセンター、またはオンライン（OnVUE） |
| 前提条件 | なし（実務経験も、ほかの資格も不要） |
| 認定の期限 | 有効期限はない。ただし「有意性の期限」があり、認定日から5年以内に再受験して合格すると有意性が保たれる |
| 再受験の規定 | なし（リテークポリシーはない） |

※ この2項目は、公式サイト（出題範囲、FAQ、申込ページ）では記載を確認できなかった。2026年8月の受験記に書かれていた値なので、申込時に確認する。

### 出題形式の補足

公式サイトには「マウスによる選択方式がほとんどですが、キーボード入力問題も多少出題されます」と書かれている。

- **入力問題の中身は公開されていない。** 何問出るのか、何を入力するのか、大文字と小文字を区別するのかは、公式の例題と受験記を調べてもわからなかった（2026-09-14 時点）。
- **選ぶ数が決まっていない問題がある。** 公式の例題には「正しいものを全て選択してください」という問題がある。消去法が使えないので、選択肢を1つずつ正しいかどうか判断できる必要がある。

対策:

- コマンド名、パラメータ名、ファイル名は、見てわかるだけでなく**正確に書ける**ようにする。入力問題で問われるとしたら、`pg_basebackup`、`listen_addresses`、`recovery.signal` のような名前だと考えられる（推測）。
- Docker の環境で実際にコマンドを打って、綴りを手で覚える。
- 各章の確認問題に、入力形式と「全て選択」形式を混ぜる。

### 重要度の読み方

重要度を合計すると 50 になり、問題数（約50問）と一致する。分野ごとの合計（S1: 8、S2: 26、S3: 16）も、配分（16% / 52% / 32%）とぴったり一致する。したがって、**重要度はおおよその出題数**と読める（ただし、公式がそう明言しているわけではない）。

ここから次のことが言える。

- **S3.1（13）、S2.4（7）、S2.5（7）の3つで合計 27**。全体の半分を超える。
- S2 運用管理には重要度 2〜7 の項目が5つあり、全体の半分を占める。
- S3.3 トランザクションは重要度 1 だが、S2.5 の VACUUM を理解する土台になる。

## Ver.3.0 の改定内容

Ver.3.0 は **2023年2月1日** に配信が始まった。PostgreSQL 12〜14 をベースにしている（Ver.2.0 とは6か月間並行して配信される予定だった）。

Silver で変わった項目は次のとおり。

| 中項目 | 追加 | 削除・移動 |
| --- | --- | --- |
| S2.1 インストール方法 | — | 削除: `pg_ctl initdb` |
| S2.2 標準付属ツールの使い方 | `pg_config`、`pg_controldata`、`pg_isready`、`pg_resetwal` | — |
| S2.4 バックアップ方法 | 非排他的低レベルバックアップ、Archive Recovery（postgresql.conf）、`backup_label`、`tablespace_map`、`recovery.signal` | 削除: `recovery.conf`。移動: `pg_start_backup()` と `pg_stop_backup()` を「主要な知識範囲」から「重要な用語」へ |
| S3.1 SQLコマンド | ストリーミングレプリケーション、ロジカルレプリケーション、`CREATE PUBLICATION/SUBSCRIPTION`、`GENERATED (AS IDENTITY)`、`JSON`、`JSONB`、JSON PATH、`CALL` | 削除: ルール（`RULE`） |

S1、S2.3、S2.5、S3.2、S3.3 は変わっていない（表記の修正だけ）。

### なぜ変わったのか

- PostgreSQL 12 で `recovery.conf` が廃止されたので、`recovery.signal` を使う方式に置き換わった。
- JSON とレプリケーションは、実務で使われる場面が増えたので追加された。改定資料では「データの多様化への対応」「データベース連携機能の追加」と説明されている。

### 教材を選ぶときの注意

Ver.2.0 向けの古い教材には `recovery.conf` や `RULE` が載っている一方で、JSON やレプリケーションが載っていない。「Ver.3.0 対応」と書かれた教材を使う。

## 試験の基準（PG 12〜14）と学習環境（PG 18.6）の違い

出題範囲は、2023年2月に PostgreSQL 12〜14 を基準にして作られた。PostgreSQL は毎年メジャーバージョンが出るので、学習に使う最新版とは挙動が違うところがある。

- 学習環境: PostgreSQL **18.6**（2026-08-13 リリースの最新安定版。19 はまだ beta なので使わない）
- 方針: **学習は 18.6 で行い、試験では 12〜14 の知識で答える**

各バージョンのリリースノートにある「互換性のない変更」から、Silver の出題範囲に関係するものを抜き出した。学習中に見つけた違いは、各章の「⚠️ 試験と最新版の違い」に追記する。

| バージョン | 変更 | 章 |
| --- | --- | --- |
| 14 ※ | `password_encryption` のデフォルトを `md5` から `scram-sha-256` に変更 | S2.3 |
| 14 ※ | 定義済みロール `pg_read_all_data`、`pg_write_all_data`、`pg_database_owner` を追加 | S2.5 |
| 15 | 排他的バックアップモードを廃止。`pg_start_backup()` と `pg_stop_backup()` を `pg_backup_start()` と `pg_backup_stop()` に改名。`pg_is_in_backup()` と `pg_backup_start_time()` を削除 | S2.4 |
| 15 | `public` スキーマの CREATE 権限を PUBLIC から削除し、所有者を `pg_database_owner` に変更 | S2.5 |
| 16 | `CREATEROLE` を持つロールが他のロールを変更するには、`ADMIN OPTION` が必要になった | S2.5 |
| 16 | `GRANT ... WITH INHERIT` を追加 | S2.5 |
| 16 | `pg_hba.conf` で正規表現と、別ファイルの読み込み（include）が使えるようになった | S2.3 |
| 16 | `promote_trigger_file` を削除 | S3.1（レプリケーション） |
| 17 | `db_user_namespace` を削除 | S2.3 |
| 18 | `initdb` がデフォルトでデータチェックサムを有効にする | S2.1 |
| 18 | MD5 パスワード認証を非推奨にした | S2.3 |
| 18 | `VACUUM` と `ANALYZE` が、継承の子テーブルもデフォルトで処理する（親だけを処理するなら `ONLY`） | S2.5 |
| 18 | `COPY FROM` で CSV を読むとき、`\.` を終端として扱わない | S2.4 |
| 18 | `NOT NULL` 制約を `pg_constraint` に格納し、名前を付けられるようにした | S3.1（テーブルと制約） |
| 18 | UNLOGGED のパーティションテーブルを禁止 | S3.1（パーティション） |
| 18 | `AFTER` トリガーを、イベントが発生した時点のロールで実行する | S3.1（DBオブジェクト） |

※ 試験の基準（12〜14）の範囲内での変更。どのバージョンを前提にした問題なのかによって、答えが変わるおそれがある。

特に注意すること:

- **`pg_start_backup()` と `pg_stop_backup()`**: 出題範囲には今も旧名で載っているが、18.6 にはこの関数が存在しない。
- **`public` スキーマの権限**: 18.6 で試すと、一般ユーザーは `public` スキーマにテーブルを作れない。試験の基準（12〜14）では作れる。
